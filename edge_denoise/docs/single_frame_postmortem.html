Single-Frame Post-Mortem

What the previous agent tried in 28 hours, what each pipeline looks like, what it actually produced, and why none of it meets the three requirements: one frame in, better edge repeatability, and fine features kept.

Verdict: no attempt beats the model we already had

Six training ideas were implemented; five were scored on one common benchmark (ten development scenes, eight fresh noisy retakes each), and the sixth, a training-only teacher, never reached a deployable model. Of the five, four are worse than the existing single-frame model on PSNR and on fine features, and worse or at best tied on edge repeatability. The fifth, whole-frame regression, is better on edge repeatability and marginally better on PSNR, but it was trained against clean images that do not exist for real SEM, and it keeps less of the fine features than the existing model.

Every single-frame arm, old and new, erases the isolated stain in scene 21. Only the 16-frame fusion model recovers it, and 16 frames at inference is not allowed. The most realistic training recipe in the batch (blind-spot models trained on raw frames only) lands about 1 dB and 0.1 px behind the existing Noise2Noise model.

Beyond the six attempts, the agent produced eight diagnostic side-studies with no trained denoiser, sixteen design and log documents, and two auto-generated HTML reports totalling 10 MB. Everything except the fusion fix and this page is quarantined, not deleted; see the last section.

The three requirements, and the numbers to beat

All numbers on this page were measured on the same 80 inputs by the agent's full-frame scorer. They are not comparable with the center-crop tables in the earlier committed reports: the existing model scores 0.477 px there and 0.763 px here, because the full-frame scorer measures 156 line-width sites across whole 512×512 frames instead of the historical center crops.

1 · Whole-frame regression partial: precision better, features worse, needs clean images

Idea give the U-Net the whole 512×512 frame instead of 64×64 tiles, so distant structure can inform each pixelTraining 1,500 updates from the existing model, clean targets, Adam 1e-4, EMA 0.99Code edge_denoise/whole_frame.py, whole_frame_study.py

The existing model never sees more than a 64-pixel tile. If a stain is erased because the network cannot tell it from noise without context, a whole-frame view should help. The agent kept the same weights and topology and only changed the spatial extent (plus a pooled attention over the whole frame), then fine-tuned two copies with an identical recipe: one on whole frames, one on tiles. To isolate the architecture question it used the clean synthetic image as the target, which real SEM does not have.

2 · SceneVAE, raw frames only fail: 3.7 dB below the existing model

Idea learn a probabilistic hidden clean scene using only the physics of photon counting, no clean image and no alignmentTraining 3,000 updates from scratch, 2.9 M parameters, raw drifting frames, 353 sCode edge_denoise/scene_vae.py, scene_vae_study.py

A hierarchical variational autoencoder: the encoder turns one raw frame into random "scene" variables at four scales, the decoder turns those into an intensity image, and the loss asks how unlikely the measured photon counts are under that intensity (Poisson, peak 10, clipped), plus the usual KL regularizer. Because the loss only ever compares the model to the very frame it was given, drift between frames is irrelevant. This is the only fully legal recipe in the batch besides the blind-spot models.

Why it does not meet the requirements

The output is mottled and contains invented blobs; surfaces that should be flat are not. The finest latent variables carried almost no information (measured KL near zero at native resolution), so the decoder was effectively painting from coarse variables. Three thousand updates from random weights is also far less training than the existing model had. The recipe is feasible; this implementation is far from competitive.

3 · Blind-spot context models fail: best raw-only arm still 0.3 dB and 0.12 px behind

Idea classic self-supervised denoising: hide a pixel, predict its intensity distribution from the neighbours, score with the photon likelihood, then fold the measured count back in with BayesTraining 10,000 updates (3a, 3b) from scratch on raw frames; 3c is a 3,000-update continuationCode edge_denoise/context_posterior.py, dense_blindspot.py, response_calibration.py, photon_augmentation.py

Three variants of the same idea. 3a, masked: 16 passes over the image, each hiding 1/16 of the pixels, predicting either a 256-level categorical distribution or a Gaussian. 3b, dense: four one-directional ("causal") networks, so every pixel is predicted in one pass and training sees 16× more targets per update. 3c, response calibration: continue a dense model while injecting known synthetic photon bumps into the training frames and penalising a wrong response to them, the hope being that a model which reacts correctly to injected features will stop erasing real ones. At inference all variants combine the neighbour-based prior with the measured pixel count, which is exact for this noise model.

Why it does not meet the requirements

A blind-spot model is structurally handicapped: the pixel it predicts is withheld, and the Bayes step can only add what one pixel's clipped count can say, which is little at peak 10. The dense variant closes most of the gap to Noise2Noise but never crosses it, and each extra idea made things worse: photon augmentation lowered contrast in all six windows, and response calibration increased the response to injected bumps while leaving the real stains erased and raising the CD spread to 1.12 px. The agent also confirmed that these models invent familiar-looking stains where none exist and erase unfamiliar ones, which is the wrong direction for metrology.

4 · Motion-marginal training on drifting pairs fail: worse than its own starting point

Idea the endorsed direction: train on drifting bursts, infer on one frame, without ever registering the framesTraining warm start from a masked Gaussian model (30.6 dB), 3,000 updates on 1,140 adjacent frame pairs, 1,024 importance particles, batch 1Code edge_denoise/motion_*.py (10 modules), motion_predictive_study.py

The student sees one frame (A) and predicts a continuous intensity field. That field is rendered under 1,024 candidate drifts (shift, in-frame shear, gain, offset) and compared to the photon counts of a neighbouring frame B from the same burst. The loss averages the likelihood over the candidate drifts, so no registration is ever computed. A second arm added synthetic photon bumps to A (an "intervention") to force a correct response to unusual features. Both arms were frozen and scored only at their final step.

Why it does not meet the requirements

The averaging over drifts collapsed: of 1,024 candidate drifts, only about 16 carried any weight, so the gradient was dominated by noise and the model drifted away from its starting point the longer it trained. The output also has a visible brightness bias (mean intensity +0.03), and the intervention arm was worse on all ten scenes. The idea of training on unregistered bursts is not disproven by this, but this implementation is not usable, and its likelihood was improving while the images got worse, which means the objective itself does not track image quality.

5 · Joint scene-and-drift teacher incomplete: not converged, no student trained

Idea instead of registering a burst and averaging it, fit one scene and all 16 drift states together, and use the fitted scene as the training target for a one-frame modelTraining 4 fits (2 TRAIN scenes × 2 random starts), 800 + 2,400 updates eachCode edge_denoise/joint_burst_teacher.py, joint_acquisition.py

This attacks the training-target problem directly. A registered burst average blurs whatever the registration gets wrong; a joint fit explains all 16 raw frames with one 512×512 scene plus 66 drift numbers, under the photon model and a wavelet prior, using variational inference. If the teacher were good, a one-frame student could be distilled from it without any clean image.

Why it does not meet the requirements

A 31 dB teacher cannot supervise a student that must beat a 37 dB baseline; distilling it would transfer its grain. The fits were still improving when stopped, so the number is a budget artefact as much as a method limit, but each fit already cost 3,200 full-scene updates for a single scene, and 76 training scenes would need this repeated for each. As built it is a research direction, not a result.

6 · Same-image geometry retrieval fail: +0.0005 dB, the model ignored the borrowed evidence

Idea repeated line patterns inside one frame are near-copies of each other; let similar patches elsewhere in the same frame vouch for the local intensity profileTraining 2 arms × 3,000 whole-frame updates, clean targets, 108 min eachCode edge_denoise/geometry_retrieval.py, tools/geometry_retrieval_study.py

A frozen guide denoiser segments the frame into two materials and computes the distance of every pixel to the nearest edge. Patches are described by their occupancy pattern, and for each 32×32 query the model retrieves up to eight similar, non-overlapping patches from the same frame and borrows only their intensity-versus-distance statistics, never pixels. A control arm receives the same channels filled with local statistics. Both arms use clean targets, so this is an architecture test, not a training recipe.

Why it does not meet the requirements

The retrieval channel did nothing: swapping it out of the trained model changed the output by one part in ten thousand. Similar patches can only vouch for what is common to the pattern, and the stains that matter are precisely the things that are unique to their location. The clean-supervised head also lost 13 points of feature contrast against the existing model, so the surrounding architecture is not a good starting point either.

7 · Fix: the one-frame arm of the fusion evaluator leaked motion from other frames kept

Files edge_denoise/fusion.py, tests/edge_denoise/test_edge_denoise_fusion.py (+4 tests)

In the committed burst-fusion evaluator, motion was estimated once per retake from all 16 frames and shared by every K-frame arm. The "K = 1" arm therefore had its single frame de-sheared with a velocity that could only be known from the other 15 frames. The fix caches registrations per (retake, K), registers only the first K frames, and makes K = 1 the untouched raw frame in every alignment mode, including the truth-aligned one.

Consequence for the committed report. The K = 1 rows of burst_fusion_report.md (fuse1 0.713 px for the frame-target model, 0.691 px for the multi-target model) were measured with the leak and have not been regenerated. Since K = 1 is the only production-legal row in that table, it should be re-run before anyone quotes it.

Where this leaves the project

The existing single-frame model is still the best production-legal arm on every score, and the 16-frame fusion is still the only thing that recovers the fine features. Two facts from this batch are worth carrying forward:

  1. Context is not the missing ingredient. Whole-frame attention with a clean target, the strongest possible version of "see more of the image", moved PSNR by 0.14 dB and left the scene-21 dot erased.
  2. Raw-only training works but costs about a decibel. The dense blind-spot model, trained from scratch on nothing but raw frames, reaches 36.7 dB against the Noise2Noise model's 37.0 dB. That is the price of not having aligned pairs, on this simulator.

Before any new idea is trained, the K = 1 rows of the burst-fusion report should be regenerated with the fixed evaluator, so the production-legal baseline on the drifting dataset is known to be clean.
